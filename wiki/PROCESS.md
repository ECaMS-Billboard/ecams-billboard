# Stone Ocean Scrum Process

## Sprint Plannings
Plannings will take place at the start of each sprint on the first Tuesday at 11 am. The final Sprint Backlog will be finalized by the end of the day. By the second Tuesday of the sprint, the Product owner will determine when all work for the Sprint is due, in order to finalize documentation for the end of the sprint in a timely manner and keep everyone on the same page. 

## Demo's and Retrospectives
Demos and Retrospectives will be conducted on the first Tuesday at 11 am of each sprint and must meet our definition of Done, which include that has to be demoable in production.

## Definition Of Done
The code is completed and has been reviewed at least once, The code has been tested for similar devices of ECaMS billboard, The code has thoughtful documentation/comments, The code is ready for deployment, The code is ready to be demoed. At least one GitHub commit to the product branch that with a commit message ‘Story [[STORY-NUMBER]] done.

## Testing 
In order to test, we test locally first, when those tests yeild the result we want, it gets pushed to the test branch. From there, assuming the test site builds correctly and has the desired result, we  merge test into main using a pull request. 

## Due DATES
We want to try to get in all documents and code pushes by sunday at noon on the last day of the sprint in order to give the Product manager time to create the documents for the end of sprint.
